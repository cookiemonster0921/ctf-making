Palimpsest - Solution Walkthrough
===================================

You have a single file, challenge.txt, containing a string that looks like:

    ERAFIQJRKJCHKTB7I4SSMLRSM54VS5ZRGY3CQRBQLM7VIQJRNZAW6TCVIBJDMSRW

This was encoded through multiple successive layers. Your job is to identify
each layer and reverse them in the right order. No key is required — all
layers are deterministic public operations.

This challenge is designed to be solved with CyberChef (https://gchef.io)
or equivalent tools.


step 1: recognise the outermost layer
---------------------------------------
Look at the string carefully:
  - Characters: only A-Z (uppercase) and digits 2-7, plus possible = at the end
  - This is the Base32 alphabet (A-Z and digits 2-7, padded with =)
  - Base64 uses A-Z, a-z, 0-9, +, / — this is NOT Base64 because there are no
    lowercase letters, no +, no /
  - Hex encoding uses only 0-9 and A-F — this string uses G-Z, so not hex

Conclusion: the outermost layer is Base32. In CyberChef: add "From Base32"
(default settings: alphabet A-Z2-7=, remove non-alphabet chars).


step 2: look at what base32 decoding produced
-----------------------------------------------
After Base32 decoding you have a string of mixed printable characters. It
does not look like the flag yet. Try reversing it — CyberChef: add "Reverse"
(By: Character).

After reversing, the result is printable ASCII containing mostly letters plus
some symbols like !, #, @, etc.


step 3: recognise ROT13
--------------------------
The reversed output is dominated by letters in an unfamiliar pattern. Many
adjacent letter pairs are not normal English words. This is the hallmark of
ROT13 (each letter shifted by 13, so A↔N, B↔O, etc.).

In CyberChef: add "ROT13" (default settings: rotate upper + lower, not
numbers, amount 13).

After ROT13 the result looks like a mixture of printable ASCII symbols with
some letters — it still isn't readable text.


step 4: recognise Base85
--------------------------
What remains after reversing and ROT13 contains characters from the ASCII85
set: printable characters in the range ! through u (ASCII 33–117). This
density of unusual symbols (!, #, $, @, etc.) combined with no spaces or
obvious structure is the fingerprint of Base85.

In CyberChef: add "From Base85" — leave the alphabet on the default "!-u"
setting and check "Remove non-alphabet chars".

The output is the flag.


cyberchef recipe (all four operations in order)
-------------------------------------------------
  1. From Base32  (alphabet: A-Z2-7=, remove non-alphabet chars: ✓)
  2. Reverse      (by: Character)
  3. ROT13        (rotate lower: ✓, rotate upper: ✓, numbers: ✗, amount: 13)
  4. From Base85  (alphabet: !-u  ← this is the default, no change needed)

CyberChef will show the flag in the Output pane after all four steps.


python decode (alternative / verification)
-------------------------------------------
    import base64, codecs

    ciphertext = open('challenge.txt').readlines()[2].strip()  # third line

    after_b32     = base64.b32decode(ciphertext + '=' * ((-len(ciphertext)) % 8)).decode()
    after_reverse = after_b32[::-1]
    after_rot13   = codecs.decode(after_reverse, 'rot_13')
    flag          = base64.a85decode(after_rot13.encode(), adobe=False).decode()

    print(flag)


what the layers were
---------------------
Encoding order (applied to the original flag):
  1. Base85 (ASCII85, !-u)  — raw flag bytes → printable ASCII
  2. ROT13                   — alphabetic characters shifted by 13
  3. Reverse                 — string reversed
  4. Base32                  — final A-Z/2-7 output in challenge.txt

Decoding order (what you did):
  1. Base32 decode
  2. Reverse
  3. ROT13
  4. Base85 decode → flag

The obscurity comes from using Base85 (uncommon) combined with reversal
(easy to miss as a "layer") and ROT13 applied to Base85 output (which
looks random at first glance, making the rotation non-obvious).
