Two Keys, One Lock - Solution Walkthrough
==========================================

You are given three files:

  ciphertext_a.hex  — an encrypted message (this contains the flag)
  ciphertext_b.hex  — a second encrypted message
  plaintext_b.txt   — the plaintext of the second message

The description says the encryption is "unbreakable". That claim is half-true:
a one-time pad (OTP) is provably unbreakable when used correctly. The catch
is that correctness requires using the key EXACTLY once. These two messages
were encrypted with the same key — which breaks the entire security property.


step 1: understand one-time pad encryption
-------------------------------------------
One-time pad encryption XORs each byte of the plaintext with the corresponding
byte of a secret key:

    ciphertext = plaintext XOR key

Decryption is the same operation:

    plaintext  = ciphertext XOR key

The key must be:
  - Random
  - At least as long as the message
  - Never reused

This last requirement is what was violated here.


step 2: understand why key reuse is fatal
------------------------------------------
If the same key is used for two messages:

    ct_a = pt_a XOR key    (flag, unknown to you)
    ct_b = pt_b XOR key    (second message, you know both ct_b and pt_b)

XOR has this property: A XOR A = 0 and A XOR 0 = A.

From ct_b and pt_b, you can recover the key:

    key = ct_b XOR pt_b

Because:  (pt_b XOR key) XOR pt_b  =  key XOR (pt_b XOR pt_b)  =  key XOR 0  =  key

Once you have the key, decrypting the flag is trivial:

    flag = ct_a XOR key[:len(ct_a)]


step 3: solve with CyberChef (recommended)
-------------------------------------------
This challenge is designed to be solved in two CyberChef recipes.

  RECIPE 1 — recover the key material:
    Input:    paste the contents of ciphertext_b.hex
    Steps:
      1. From Hex   (leave all settings at defaults)
      2. XOR        (key type: UTF8,
                     key: paste the entire content of plaintext_b.txt)
      3. To Hex     (delimiter: None)
    Output:   the key material as a hex string — copy this for Recipe 2.

  RECIPE 2 — decrypt the flag:
    Input:    paste the contents of ciphertext_a.hex
    Steps:
      1. From Hex   (leave all settings at defaults)
      2. XOR        (key type: Hex,
                     key: paste the hex string from Recipe 1)
    Output:   the flag in CSEC{...} format.

Note: in CyberChef's XOR, if the key is longer than the input it is
truncated automatically — you can paste the full key hex from Recipe 1
without trimming it.


step 4: solve with Python (alternative)
-----------------------------------------
    ct_a_hex = open('ciphertext_a.hex').read().strip()
    ct_b_hex = open('ciphertext_b.hex').read().strip()
    pt_b     = open('plaintext_b.txt').read().strip().encode()

    ct_a = bytes.fromhex(ct_a_hex)
    ct_b = bytes.fromhex(ct_b_hex)

    key  = bytes(x ^ y for x, y in zip(ct_b, pt_b))
    flag = bytes(x ^ y for x, y in zip(ct_a, key))
    print(flag.decode())


what just happened — the short version
----------------------------------------
The one-time pad was invented in 1917 and is the ONLY encryption scheme
with a mathematical proof of perfect secrecy — if used correctly.

"Correct use" means the key must be:
  1. Truly random
  2. At least as long as the message
  3. Used EXACTLY ONCE and then destroyed

In practice, condition 3 is the hardest to maintain. During World War II,
Soviet intelligence accidentally reused OTP pages in the VENONA project,
allowing US and UK cryptanalysts to decrypt thousands of messages over
several decades.

The mathematical reason key reuse is fatal: if you have ct_a XOR ct_b (which
equals pt_a XOR pt_b), and you know either plaintext, you can recover the
other. Even without knowing a plaintext, frequency analysis against the XOR
of two English plaintexts can often recover both.
